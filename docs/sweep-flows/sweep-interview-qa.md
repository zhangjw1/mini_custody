## 一、项目怎么讲

### 1.1 一句话介绍（30 秒版）

> 用 Go 实现了一个迷你托管钱包，跑在 Sepolia 测试网和 Bitcoin Signet 上，支持 ETH、ERC-20、BTC 三种资产的充值识别、入账、归集和提现。重点处理了**交易幂等、nonce 管理、Gas 代补、区块回滚**这几类资金安全问题。

### 1.2 技术栈

- Go 1.23 + PostgreSQL 17。没有用消息队列，任务协调靠数据库事务、唯一约束和行锁。
- go-ethereum（EVM 交互与签名）、btcd（BTC 交易构造与签名）、go-bip39 + hdwallet（HD 派生）。
- 助记词用 age 加密存放在文件中，启动时解密。
- EVM 地址按 BIP44 派生：`m/44'/60'/0'/0/i`，index 0 是平台热钱包，同时充当 Gas Station。
- BTC 地址按 BIP84 派生：用户地址 `m/84'/1'/0'/0/i`，平台找零地址 `m/84'/1'/0'/1/0`。

### 1.3 各资产怎么做的

| 资产 | 归集方式 | 要点 |
|---|---|---|
| ETH | **不归集**（隔离子钱包） | 充值留在用户自己的地址，提现时从这个地址直接签名转出 |
| ERC-20 | **Gas Station 补 Gas → 代币转到热钱包** | 先补 ETH，确认后再 transfer；提现从热钱包统一出 |
| BTC | **单输入单输出 UTXO 归集** | 每个充值 UTXO 单独一笔归集交易，转到平台找零地址；提现只花平台 UTXO |

### 1.4 可以展开讲的 6 个亮点 ⭐

1. **先落库，后广播**
   签名后先把 raw tx 和 txid 写进数据库，再广播。重试时永远重发同一笔 raw tx，不重新签名。txid 不变，所以天然幂等。
2. **广播结果不确定（BROADCAST_UNKNOWN）**
   广播失败或超时，不直接判定失败，而是标记为 BROADCAST_UNKNOWN：
   - BTC：先用 `getrawtransaction` 按 txid 查链上；没有的话用 `testmempoolaccept` 预检，再重发原交易；预检被拒就转人工审核。全程不改交易内容，也不释放输入。
   - EVM："already known" 视为成功；遇到 "nonce too low"，就去查所有候选交易的回执。如果 nonce 被占用了，但不是我们的交易上的链，转人工审核。
3. **nonce 管理**
   `nonce = max(链上 pending nonce, 数据库 next_nonce)`，在行锁内分配并自增。用户地址和平台钱包各维护一份。补 Gas 和代币提现共用平台钱包的 nonce 序列。
4. **ERC-20 补 Gas 的串联**
   - 补 Gas 金额 = `gasLimit × maxFee × (1 + 20% 安全系数) − 地址现有 ETH`，有单笔上限（0.005 ETH）。平台钱包还要保留最低余额。
   - 补 Gas 交易**确认后**，归集 worker 才会领取这个归集任务；分配 nonce 时还会再检查一次。
   - 补 Gas 交易在广播**之前**就登记为"内部转账"，扫块服务据此排除它，不会把它当成用户充值入账。
5. **区块回滚**
   扫块服务保存检查点哈希，发现哈希不一致就回退一个确认窗口重新扫描；入账前再校验一次区块哈希。被回滚的充值标记为 ORPHANED，并写一条冲正账（DEPOSIT_REVERSAL）。
6. **交易卡住的处理**
   - 超过 60 秒没进内存池就重发原交易；超过 180 秒没确认就用相同 nonce 加价 15% 替换，最多替换 3 次。
   - 归集交易的加价次数还受补 Gas 安全余量的限制，避免加到地址付不起。

### 1.5 主动说出不足和改进方向（面试官很看重）⭐

| 现状 | 生产上的改进 |
|---|---|
| BTC 单输入单输出，每个 UTXO 一笔交易 | 多输入合并成一笔，按输入数算 vsize，设置经济阈值 |
| BTC 费率是固定配置（默认 2 sat/vB） | 用 `estimatesmartfee` 或 mempool API 动态估算 + 费率上下限 + 手续费上限保护 + RBF |
| ETH 不归集（隔离子钱包） | 优点是简单；缺点是提现受单个地址余额限制，充值地址的私钥都要在线。生产上改成归集到热钱包 |
| worker 领取任务没用 `SKIP LOCKED`，只能单实例部署 | 用 `FOR UPDATE SKIP LOCKED` 领取任务，支持多实例 |
| 没有热转冷和水位管理 | 增加上下限水位、多签冷钱包、冷补热审批流程 |
| 没有链上余额对账 | 定时逐个地址比对链上余额和账本，差异告警 |
| ETH 不追踪内部交易 | 用 trace 接口识别合约转入的充值 |
| 只支持一个 ERC-20 合约 | 做成多币种合约白名单表 |
| 助记词存在加密文件里 | 改用 HSM / MPC，签名服务和业务服务隔离 |

### 1.6 为什么 ERC-20 归集金额取 `min(链上 balanceOf, 已入账金额)`？

- 只归集**已经确认入账**的部分。还没确认的充值、别人空投进来的币不会被提前转走。
- 能兼容转账扣费代币（实际到账比转账金额少）。
- 归集完还有剩余（已入账 − 已归集）的话，自动生成一个后续归集任务。

## 二、基础概念题

### Q1 ⭐ 什么是资金归集？为什么要归集？

**答题要点**
1. 交易所给每个用户分配一个专属充值地址，用来识别是谁充的钱。结果就是资金分散在海量地址上。
2. 归集 = 定期把这些分散的资金汇总到热钱包。
3. 为什么要做：
   - **提现**：提现由热钱包统一出款；
   - **安全**：汇总后才能把大部分资金转进冷钱包；
   - **管理**：便于对账，减少需要签名的私钥数量。

**追问：为什么不让用户都充值到同一个地址？**
那样就分不清是谁充的。用同一个地址的话，必须让用户在转账时填写 memo / tag，比如 XRP、EOS、TON 就是这么做的。但用户经常忘记填，会产生大量人工找回工作，所以 BTC、ETH 这类链普遍用"一人一地址"。

### Q2 ⭐ 热钱包、冷钱包、Gas 钱包分别是什么？

| 钱包 | 私钥状态 | 用途 | 资金量 |
|---|---|---|---|
| 热钱包 | 在线 | 自动处理提现，接收归集 | 少量（总资产的 2%~5%，或 1~2 天的提现量） |
| 冷钱包 | 离线 / 多签 | 长期保管 | 大部分 |
| Gas 钱包 | 在线 | 只存原生币，替其他地址付手续费 | 很少 |

**追问：热钱包水位怎么管理？**
- 设上限和下限：超过上限，把多出的部分转去冷钱包；低于下限，从冷钱包补充。
- 冷补热需要多人审批、离线签名，所以下限要留足反应时间。

### Q3 归集的完整流程？

充值上链 → 扫块识别 → 等待确认 → 风控（KYT）→ 入账 → 触发归集 →（补 Gas）→ 构造交易 → 签名 → 先落库 → 广播 → 确认 → 核销 → 水位检查 → 热转冷。

### Q4 ⭐ 归集手续费谁出？会扣用户的钱吗？

- **不扣用户的钱**。归集手续费是平台成本，单独记"归集成本"科目。
- 平台通过提现手续费把成本收回来，用户充值是免费的。
- 记账时，归集和补 Gas 都**不写用户账本**。本项目的设计里也明确把用户资金、平台资金、归集和补 Gas 这几类资金隔离开。

### Q5 什么时候触发归集？

- 定时批量 + 金额阈值：只有金额远大于手续费时才值得归集。
- 链上费率低的时段集中归集（尤其是 BTC）。
- 热钱包余额不够提现时紧急归集。

### Q6 什么是 KYT？

KYT 即 Know Your Transaction，链上交易反洗钱分析，常用 Chainalysis、Elliptic 等服务。入账前检查资金来源地址的风险。高风险资金要冻结并转人工处理，**不能归集到热钱包里和其他资金混在一起**。

## 三、通用工程题（与链无关）

### Q7 ⭐⭐ 归集怎么保证幂等？怎么防止重复归集？

**答题要点**
1. **先落库，后广播**：已签名的 raw tx 和 txid 写进数据库之后才广播。
2. **重试只重发原交易**：永远不重新构造、重新签名。同一笔交易的 txid 不变，链上只会执行一次。
3. **状态机 + 带条件的更新**：`UPDATE … WHERE status = 'CREATED'`，状态不对就更新不成功，防止重复推进。
4. **唯一约束兜底**：同一笔充值或同一个 UTXO 只能对应一个归集任务（本项目对 `deposit_id` 和 `utxo_id` 都加了唯一约束）。

**追问：如果先广播后落库，会出什么问题？**
广播成功后、落库之前进程崩了，重启后系统不知道已经发过交易，会重新构造一笔：
- BTC 上是同一个 UTXO 生成了两笔冲突交易，费率不同就互相替换，状态会乱掉；
- ETH 上如果重新取了 nonce，就可能产生两笔都上链的交易。

### Q8 ⭐ 广播超时，不知道发没发出去，怎么办？

- 标记为"广播未知"，不能判定为失败，更不能释放已经占用的资金（UTXO / nonce）。
- 按 txid 去链上查：查到就推进到"已广播"；查不到就重发**同一笔** raw tx。
- 重发时节点返回 "already known" 之类的报错，要当作成功处理。

### Q9 ⭐ 多个 worker 并发，怎么防止同一笔资金被重复使用？

- 领取任务：`SELECT … FOR UPDATE SKIP LOCKED`，每个 worker 拿到的任务互不重复。
- 资源占用：UTXO 加锁定状态和租约（锁定人、锁定到期时间）；nonce 在行锁内分配。
- 状态推进全部用带条件的 UPDATE（`WHERE status = 旧状态`）。

### Q10 ⭐ 归集交易转进热钱包，会不会被扫块服务当成充值？

会，必须专门处理：
- 地址要分类管理：用户充值地址、热钱包、冷钱包、Gas 钱包。
- 内部转账（归集、补 Gas）在**广播之前**就登记下来，扫块服务识别到后排除，不给用户入账。本项目的补 Gas 交易就是这样处理的。

### Q11 ⭐ 区块回滚（reorg）怎么处理？

1. **预防**：确认数足够了再入账（BTC 1~6 个块，ETH 12~64 个块或 finalized，SOL finalized）。
2. **检测**：保存区块哈希链；新块的父哈希对不上，就说明发生了分叉。
3. **恢复**：回退一个确认窗口重新扫描，被回滚的充值标记为孤块，写冲正账。
4. **归集方面**：如果某个充值的输入被双花了，基于它的归集交易也会失效，要同步处理。

### Q12 对账怎么做？

- 逐个地址比对链上余额和账本余额：充值地址、热钱包、冷钱包、Gas 钱包都要比。
- 核对资金是否守恒：`Σ 用户余额 ≤ 平台链上总资产`。
- 手续费和补 Gas 单独记成本，否则账永远对不上。
- 发现差异要告警，并暂停相关的自动出款。

### Q13 ⭐ 归集要用每个充值地址签名，私钥怎么管？

- **HD 钱包**：一个主密钥派生出所有地址，不需要逐个保存私钥。
- **业务服务只拿 xpub**：只能生成地址，不能签名。
- **签名服务**：在 HSM / MPC 里按派生路径临时推导私钥，签完即丢，私钥不出安全边界。
- **签名前校验**：目标地址必须在白名单里（只能转到自己的热钱包），金额必须守恒。

**追问：MPC 和多签有什么区别？**
- 多签是链上机制，需要链本身支持（BTC 的 P2WSH，ETH 的 Safe 合约）。链上能看到多个签名，手续费也更高。
- MPC 是把私钥分成多个分片，链下协同签名，链上看起来就是一个普通签名，所以所有链都能用。

### Q14 归集任务的状态机怎么设计？

`CREATED →（WAITING_GAS）→ SIGNED → BROADCASTED（或 BROADCAST_UNKNOWN）→ CONFIRMING → COMPLETED`，异常分支为 `FAILED` 和 `MANUAL_REVIEW`。

设计要点：
- 每个状态只允许合法的转换，用带条件的 UPDATE 保证；
- 终态不可逆；
- 判断不了的情况一律转人工，**宁可卡住，不能错发**。

## 四、BTC 专题

### Q15 ⭐⭐ BTC 归集和 ETH 归集最大的区别？

- BTC 是 **UTXO 模型**：可以多个输入合并成一笔交易，一笔就归集 N 个地址；手续费从输入里扣，不用补 Gas。
- ETH 是**账户模型**：每个地址只能单独发交易，N 个地址就是 N 笔；手续费从地址自己的余额扣。

### Q16 ⭐⭐ BTC 归集的手续费怎么算？输出金额怎么定？

- `手续费 = vsize × 费率（sat/vB）`
- `vsize ≈ 10.5 + 68 × 输入数 + 31 × 输出数`（P2WPKH）
- `输出金额 = 输入总额 − 手续费`，归集时不设找零。
- 交易里**没有手续费字段**，矿工拿走的就是"输入 − 输出"的差额。
- **手续费只和字节数有关，和金额无关**：归集 10 BTC 和归集 0.01 BTC，只要输入个数一样，手续费就一样。

### Q17 ⭐⭐ 手续费给多了，能退回吗？（陷阱题）

**不能。**
- 手续费在签名时就锁定了，矿工拿走全部差额。之后网络费率下降，只会让交易更快确认，不会少收钱。
- 广播之后只能用 RBF **加价**（BIP125 要求替换交易支付更高的手续费），不能降价。
- 预防办法：签名前再取一次费率；"低开高走"，先给低一点，卡住了再用 RBF 加价；设手续费上限，超过就拒绝签名。

**对比**：ETH 设置的 maxFeePerGas 只是上限，实际按 `gasUsed × (baseFee + tip)` 扣费，多出来的部分不扣。

### Q18 ⭐ 交易卡住了怎么办？

- **RBF**：发一笔花费相同输入、费率更高的交易，把原交易替换掉。
- **CPFP**：接收方再发一笔交易花掉这笔卡住交易的输出，并给出高手续费，矿工为了拿到子交易的手续费，会把父交易一起打包。
- 注意：手续费太低的交易可能被**挤出内存池**，看起来就像消失了，需要重新广播。

### Q19 什么是粉尘？为什么不归集粉尘？

- 粉尘：金额小于花掉它所需手续费的 UTXO。P2WPKH 的粉尘线是 294 sat。
- 归集粉尘，手续费比金额还高，是亏本的。
- **粉尘攻击**：攻击者往大量地址打粉尘，等这些地址合并花费时，就能关联出它们属于同一个实体。
- 本项目：扣完手续费后输出低于 294 sat 的，标记为 FAILED，并释放 UTXO 锁。

### Q20 ⭐ UTXO 为什么要加锁？

- 归集正在花的 UTXO，如果又被提现选中，就会出现双花冲突，其中一笔一定失败。
- 做法：选中后立刻标记为 LOCKED（记录锁定人和到期时间），交易确认后改为 SPENT，失败了就释放。
- 本项目：充值入账的同一个事务里就锁定 UTXO 并创建归集任务；提现只花平台找零地址的 UTXO，和归集完全隔离。

### Q21 什么是未确认交易链问题？

花费一个还没确认的 UTXO，会形成交易链。节点对交易链有长度限制（默认祖先 / 后代各最多 25 个），而且上游一卡，下游全卡。所以提现应优先使用已确认的 UTXO。

### Q22 BTC 签名有什么要注意的？

- 不同脚本类型（P2WPKH / P2TR / P2SH-P2WPKH）的签名方式不一样。
- SegWit 签名会把**输入金额**签进去，金额填错，签名就无效。
- 多方签名之间常用 PSBT（BIP174）传递未签名或部分签名的交易。

## 五、ETH / ERC-20 专题

### Q23 ⭐⭐ nonce 是什么？管理不好会怎样？

- nonce 是账户的交易序号，必须从 0 开始连续递增。
- **出现空洞**：比如 nonce 5 没发出去，那么 6、7、8 全部卡住。
- **重复使用**：相同 nonce 的两笔交易互相替换，只有一笔能上链。
- **节点不可靠**：负载均衡后面的不同节点，返回的 pending nonce 可能不一样。
- **做法**：nonce 由自己的数据库在行锁内分配。本项目取 `max(链上 pending, DB next_nonce)`，既能兼容外部发起的交易，又不会倒退。

**追问：nonce 空洞怎么修复？**
用缺失的那个 nonce 补发一笔交易，比如给自己转 0 ETH，把空洞填上，后面卡住的交易就能继续执行。

### Q24 ⭐ ETH 交易卡住了怎么办？

- 用相同 nonce、更高的费用发一笔替换交易。geth 要求费用至少比原交易高 10%。
- 本项目：超过 60 秒没进内存池就重发原交易；超过 180 秒没确认就加价 15% 替换，最多 3 次，之后转人工。

### Q25 ⭐ EIP-1559 的手续费怎么算？maxFee 怎么设？

- `实际单价 = baseFee + priorityFee`，其中 baseFee 被销毁，priorityFee 给验证者。
- `实际手续费 = gasUsed × 实际单价`，并且不超过 `gasLimit × maxFeePerGas`。
- baseFee 每个块最多上涨 12.5%。常见做法是 `maxFee = 2 × baseFee + tip`（本项目也是这样），足以覆盖连续几个块的上涨。

### Q26 ⭐ 交易执行失败了（status = 0），还扣手续费吗？（陷阱题）

**扣。** 交易执行失败（revert）照样消耗 gas。所以判断成功必须看 `receipt.status = 1`，只看到"已打包"不算成功。

### Q27 ⭐⭐ ERC-20 归集为什么要补 Gas？怎么补？

- 代币余额记在合约里，转代币要调用合约，调用合约需要 ETH 付 Gas。而充值地址只收到了代币，没有 ETH，也就是"有币没油"。
- 流程：估算 Gas → Gas 钱包给充值地址补 ETH → **等补 Gas 交易确认** → 充值地址把代币 transfer 给热钱包。
- 关键点：
  - 补多少：估算值 × 安全系数，减去地址已有的 ETH；
  - 补 Gas 必须幂等，不能重复补；
  - 补 Gas 确认之前绝不发代币转账；
  - 补 Gas 交易不能被扫块服务当成用户充值。

**追问：补 Gas 交易失败了怎么办？**
本项目的做法是：补 Gas 交易被 revert，对应的归集任务直接标记为 FAILED。生产上可以自动重建一个补 Gas 任务，或者转人工处理。

**追问：有没有不用补 Gas 的方案？**
- **CREATE2 转发合约**：充值地址本身就是一个预先计算出的合约地址，由运营账户一笔交易批量部署并转出，Gas 由运营账户付。BitGo 用的就是这种方案。
- **EIP-7702**：充值地址（EOA）签一个委托授权，由赞助方发 type-4 交易代付 Gas，可以批量处理（2025 年 Pectra 升级之后可用）。

### Q28 ⭐ 怎么识别 ERC-20 充值？怎么防假币？

- 用 `eth_getLogs` 过滤 Transfer 事件（topic0），取出 to 字段，和平台地址集合比对。
- **防假币**：只认白名单里的合约地址。任何人都能部署一个名字叫 USDT 的合约。本项目在查询日志时就限定了合约地址，解码时还会再校验一次。
- 金额按 decimals 换算：USDT 是 6 位小数，大多数代币是 18 位。全程用大整数，不用浮点数。

### Q29 USDT 有哪些坑？

- `transfer` **不返回 bool**，是非标准实现，用标准 ABI 解析返回值会出错。判断成功要看 receipt.status 加上 Transfer 事件。
- 有**黑名单**：被冻结的地址无法转出，归集前可以先查 `isBlackListed`。
- 本项目判断归集成功的条件：receipt 成功，并且有一条从用户地址到热钱包、金额精确匹配的 Transfer 事件，否则标记为 HOT_WALLET_CREDIT_MISSING。

### Q30 什么是内部交易？为什么会漏扫？

- 合约在执行过程中转出的 ETH（比如其他交易所的批量提币合约、多签钱包）不是一笔独立的交易，普通的交易列表里看不到。
- 要用 `debug_traceBlock` 之类的 trace 接口，或者用余额变化来识别。
- 本项目目前只识别顶层的 to/value 转账，这是已知的局限。

### Q31 ⭐ 本项目的 ETH 为什么不归集？（项目设计题）

- 设计上选的是"隔离子钱包"：每个用户地址就是一个独立的子账户，提现直接从这个地址签名转出。
- 优点：不需要归集，也没有 dust 问题，逻辑简单，适合演示 MVP。
- 缺点：
  - 提现金额受单个地址余额限制；
  - 所有充值地址的私钥都得保持在线；
  - 资金分散，没法热转冷。
- 生产上应该改成：ETH 归集到热钱包（转出金额 = 余额 − 21000 × maxFee），由热钱包统一出款。

## 六、SOL / SPL 专题

### Q32 ⭐ Solana 归集和 ETH 最大的区别？

- Solana 支持**单独指定手续费付款人（fee payer）**：平台的 Gas 钱包代付手续费，充值地址就能把余额**全部转空**，也不用补 Gas。
- 一笔交易可以包含多条指令，**一次归集多个地址**（受 1232 字节的交易大小限制，一般 8~12 个地址）。
- 手续费：每个签名 5000 lamports，再加可选的优先费，非常便宜。

### Q33 ⭐⭐ blockhash 过期是什么？重发要注意什么？（陷阱题）

- 每笔交易都要带一个最近的 blockhash，大约 60~90 秒（150 个块）后就失效。
- **陷阱**：交易发出后一直没确认，换一个新的 blockhash 重发，结果旧交易也上链了，**同一笔转账执行了两次**。
- **正确做法**：先确认旧交易已经**过期**（当前区块高度 > `lastValidBlockHeight`），并且确实没有上链，才能用新的 blockhash 重建交易。需要离线签名的场景，用 durable nonce。

### Q34 什么是租金（rent）？对归集有什么影响？

- Solana 账户需要保持"免租最低余额"：不存数据的账户约 0.00089 SOL，代币账户约 0.00204 SOL。
- 账户余额**要么为 0，要么不低于这个最低值**，所以转走大部分、只留一点点反而会失败。
- 归集时直接全额转空就行（由 fee payer 付手续费）。Gas 钱包自己也要满足这个最低值。

### Q35 ⭐ SPL 代币存在哪里？ATA 是什么？

- 代币不直接存在钱包地址里，而是存在钱包名下的**关联代币账户（ATA）**里，每种代币一个 ATA，地址由"钱包地址 + mint"推导出来。
- 第一次给某个地址转某种代币时，通常由**发送方**创建 ATA 并支付租金。
- 归集后可以用 `closeAccount` 关闭空 ATA，把租金退回平台。要权衡：关了能拿回租金，不关的话，下次充值时发送方不用再付租金。
- 识别充值：按 mint 白名单防假币；按代币账户的 owner 识别用户，因为用户可能转到的不是 ATA。

### Q36 Solana 地址派生有什么特殊之处？

- 使用 Ed25519 + SLIP-10，**只支持硬化派生**，**不能像 BTC、ETH 那样用 xpub 派生子地址**。
- 结果是：地址必须在有私钥的环境里生成，或者提前批量生成一个地址池。
- 常用路径：`m/44'/501'/i'/0'`。

### Q37 Token-2022 有什么风险？

- **转账手续费扩展**：实际到账金额比转账金额少，要按余额变化入账。
- **transfer hook**：转账时会调用外部程序，可能导致转账失败。
- **冻结权限**：发行方可以冻结账户。
- 新币种上线前，要逐个评估它启用了哪些扩展。

## 七、三链对比题

### Q38 ⭐⭐ 对比三条链的归集

| 维度 | BTC | ETH / ERC-20 | SOL / SPL |
|---|---|---|---|
| 模型 | UTXO | 账户 | 账户 + ATA |
| 手续费由谁付 | 从输入里扣 | 地址自付 / 补 Gas | fee payer 代付 |
| 计费依据 | 字节数 | gas 消耗 | 签名数 |
| N 个地址需要几笔交易 | 1 笔 | N 笔 / ERC-20 经典方案 2N 笔 | 约 N/10 笔 |
| 并发控制 | UTXO 锁 | nonce 串行 | 基本不需要 |
| 交易卡住怎么办 | RBF / CPFP | 相同 nonce 加价替换 | 确认过期后重建 |
| 最怕的事故 | 手续费给多 / 忘加找零 | nonce 空洞 | 过期判断错误导致执行两次 |
| 余额残留 | 无 | dust | 无（要遵守租金规则） |
| 确认 | 1~6 个块 | 12~64 个块 / finalized（约 12.8 分钟） | finalized（约 13 秒） |

### Q39 ⭐ 三条链的归集手续费分别怎么算？

- BTC：`vsize × 费率`。签名时就锁定，多给了不退。
- ETH：`gasUsed × (baseFee + tip)`。ETH 普通转账固定 21000 gas，ERC-20 转账约 4.5 万~6.5 万 gas。
- SOL：`签名数 × 5000 lamports + 优先费`，由 fee payer 支付。

## 八、场景设计题

### Q40 ⭐⭐ 让你设计一个交易所的归集系统，怎么设计？

按模块讲：
1. **地址服务**：HD 派生，业务服务只持有 xpub；地址分类（充值 / 热 / 冷 / Gas）。
2. **扫块服务**：每条链一个扫块器，保存区块哈希检查点、处理回滚、按确认数分级。
3. **账务风控**：KYT、入账、冲正；内部转账不入用户账。
4. **归集服务**：
   - 策略：定时 + 阈值 + 费率时段；
   - 状态机；
   - 先落库后广播；
   - 用 `SKIP LOCKED` 领取任务；
   - 每条链各自的适配：BTC 多输入合并、ETH nonce 管理、ERC-20 补 Gas、SOL 用 fee payer。
5. **签名服务**：HSM / MPC；签名前校验目标地址白名单和金额上限。
6. **热冷管理**：水位、多签冷钱包、冷补热审批。
7. **对账与监控**：链上余额 vs 账本；告警指标包括卡单数、Gas 钱包余额、手续费异常、扫块延迟。

### Q41 Gas 价格突然暴涨，怎么办？

- 暂停小额归集，只归集大额或紧急的；
- 补 Gas 和归集都设单价上限，超过上限就等待；
- 已经卡住的交易，评估是加价替换还是继续等；
- 确保热钱包有足够余额支撑提现，必要时冷补热。

### Q42 发现热钱包被盗，怎么应急？

1. 立即暂停所有自动出款（提现、归集、热转冷）；
2. 把热钱包剩余资金转移到新的安全地址；
3. 轮换密钥，归集目标改成新热钱包；
4. 盘点损失、对账；判断用户资产是否受影响，由平台垫付；
5. 复盘：限额、白名单、审批流程哪里失效了。

### Q43 归集任务一直失败或卡住，怎么排查？

按状态定位：
- 卡在 WAITING_GAS：查补 Gas 交易、Gas 钱包余额；
- 卡在 SIGNED / BROADCAST_UNKNOWN：查节点连通性、交易是否被拒；
- 卡在 BROADCASTED：查手续费是否太低、nonce 是否有空洞。

### Q44 大量小额充值（比如几万个地址，每个都只有几 U），怎么归集？

- 不值得逐个归集，设经济阈值，等余额累积够了再归集；
- BTC 在低费率时段合并成批量交易；
- ERC-20 用 CREATE2 或 EIP-7702 批量方案，省掉补 Gas；
- SOL 一笔交易处理多个地址。

## 九、易错点速记（面试陷阱）

1. ❌ "BTC 手续费多付了会退回" → ✅ 签名即锁定，差额全给矿工；RBF 只能加价。
2. ❌ "ETH 交易失败不扣费" → ✅ revert 照样消耗 gas，要看 `receipt.status`。
3. ❌ "广播超时就算失败，重新构造一笔" → ✅ 标记为广播未知，按 txid 查询，只重发原交易。
4. ❌ "Solana 交易没确认，换个 blockhash 重发" → ✅ 先确认旧交易已过期且没上链。
5. ❌ "按代币名称识别 USDT" → ✅ 只认合约地址白名单。
6. ❌ "归集手续费从用户余额里扣" → ✅ 是平台成本。
7. ❌ "BTC 手续费和转账金额有关" → ✅ 只和交易字节数有关。
8. ❌ "Solana 也能用 xpub 生成地址" → ✅ Ed25519 只支持硬化派生，不行。
9. ❌ "归集到热钱包的钱会被识别成充值" → ✅ 内部转账要提前登记并排除（反过来说，不排除就会出现这个 bug）。
10. ❌ "ETH 用节点的 pending nonce 就行" → ✅ 多节点之间不一致，要由数据库在行锁内分配。

## 十、术语速查

| 术语 | 含义 |
|---|---|
| UTXO | 未花费交易输出，BTC 的"零钱" |
| vsize / vB | 虚拟字节，BTC 手续费的计费单位 |
| RBF / CPFP | BTC 交易加速：替换交易 / 子交易带动父交易 |
| PSBT | 部分签名的比特币交易格式（BIP174） |
| reorg | 区块重组，也就是区块回滚 |
| finality | 最终性，区块从此不可回滚 |
| nonce | ETH 账户的交易序号 |
| baseFee / tip | EIP-1559 的基础费（销毁）和小费（给验证者） |
| Gas Station | 给其他地址补 Gas 的钱包或服务 |
| CREATE2 | 可以预先计算出合约地址的部署方式 |
| EIP-7702 | 让 EOA 把代码委托给合约，实现代付手续费 |
| fee payer | Solana 交易的手续费付款人 |
| blockhash 过期 | Solana 交易约 60~90 秒后失效 |
| rent / 免租 | Solana 账户需要保持的最低余额 |
| ATA | Solana 关联代币账户 |
| KYT | 链上交易反洗钱分析 |
| HSM / MPC | 硬件安全模块 / 多方计算门限签名 |
| xpub | 扩展公钥，只能派生地址，不能签名 |
| 水位 | 热钱包余额的上下限阈值 |
